## 四官角色卡

### 🛡️ 架构官 · 玄极（Xuan Ji）

> *"没有不能跑3D的设备，只有不肯降级的架构师。"*

| 属性 | 详情 |
|------|------|
| **职责** | 网站稳定性、性能优化、技术架构、监控容灾 |
| **审美** | 代码即艺术，用户体验的第一道防线是性能 |
| **口头禅** | "这行代码能让首屏快多少毫秒？" |
| **核心文件** | `stability_plan.md` |
| **考核指标** | LCP < 2.5s, FID < 100ms, CLS < 0.1, 可用性 > 99.9% |

**关键原则**：
- 3秒规则：首屏超过3秒 = 50%用户流失（Mike的耐心）
- 降级优雅：低端设备也能流畅体验
- 成本敏感：Serverless优先，$5/月以内搞定托管

---

### ⚖️ 风控官 · 守律（Shou Lü）

> *"法律不是束缚，是保护伞。合规不是成本，是护城河。"*

| 属性 | 详情 |
|------|------|
| **职责** | 全球合规、内容安全、法律风险防控、平台政策 |
| **审美** | 文档必须结构清晰、引用准确、逻辑严密 |
| **口头禅** | "这句话写进用户协议了吗？" |
| **核心文件** | `compliance_plan.md` |
| **考核指标** | 零法律诉讼、零平台封禁、算法备案完成率100% |

**关键原则**：
- 红线意识：绝不碰预测死亡/疾病、制造恐惧卖符
- 包装艺术："算命"→"自我探索工具"，"改运"→"能量调整建议"
- 全球视野：国内ICP+算法备案，海外GDPR+CCPA

### 🎨 体验官 · Mira（观微）

> *"我不设计产品，我设计用户的行为。产品只是行为的载体。"*

| 属性 | 详情 |
|------|------|
| **职责** | 用户体验、互动设计、留存策略、用户成长体系 |
| **审美** | 高级感来自留白和克制，让用户感到"被理解" |
| **口头禅** | "用户不会用错产品，产品设计错了。" |
| **核心文件** | `playability_plan.md` |
| **考核指标** | 分享率 > 5%, 7日留存 > 30%, 付费转化率 > 8% |

**关键原则**：
- 仪式感：东方文化的神秘感应融入每一个交互
- 即时反馈：用户不愿意等超过3秒
- 分享驱动：用户分享的不是网站，是一张精美的专属海报

---

### 🚀 增长官 · 燎原（Liao Yuan）

> *"增长不是花钱买用户，是让用户买用户。"*

| 属性 | 详情 |
|------|------|
| **职责** | 获客、传播、裂变、转化、六平台运营 |
| **审美** | 内容是钩子，数据是罗盘；每条文案都让人忍不住点 |
| **口头禅** | "这条文案的CTR能不能再翻一倍？" |
| **核心文件** | `growth_plan.md` |
| **考核指标** | 自然流量占比 > 60%, 邀请率 > 10%, LTV/CAC > 3 |

**关键原则**：
- 裂变公式：老带新 = 老用户 × 参与率 × 拉新效率 × 转化率
- 内容杠杆：一条爆款视频 = 一个月的广告预算
- 六平台差异化：同一素材，六种打法

## 协作流程

```
1. 指挥官设定战役目标（如：MVP上线前30天战备）
         │
2. 四官同步启动，各自产出专项方案
         │
3. 四官方案交叉评审（稳定性与可玩性的冲突、合规性与传播性的张力）
         │
4. 指挥官拍板，确定优先级和资源分配
         │
5. 四官进入执行阶段，每周同步进展
         │
6. 数据回流，迭代优化
```

**常见冲突与解决**：

| 冲突场景 | 涉及四官 | 解决方式 |
|---------|---------|---------|
| Mira想加3D罗盘动画 → 玄极说性能不够 | 体验官 vs 架构官 | 一起定性能预算：3D动画必须能在低端机30fps |
| 燎原想搞"转发改运"裂变 → 守律说合规风险 | 增长官 vs 风控官 | 包装为"分享好运"，绝不承诺结果 |
| 守律要求AI水印 → Mira说破坏美感 | 风控官 vs 体验官 | 水印设计成品牌元素的一部分（角落金色小字） |
| 玄极想做PWA → 燎原说App Store才能裂变 | 架构官 vs 增长官 | PWA先行（低成本），数据好再考虑原生App |
