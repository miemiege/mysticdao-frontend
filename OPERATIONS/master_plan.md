## 一、总纲概述

MysticDao 已从"产品打磨期"进入"运营战备期"。本总纲由 **四官并行研究、指挥官整合拍板**，覆盖网站上线前必须解决的四大维度：

```
┌─────────────────────────────────────────────────────────────┐
│  稳定性 · 合规性 · 可玩性 · 传播性                           │
│                                                             │
│  不是四张清单，是一个系统。                                  │
│  四个维度互相咬合，缺一即崩。                                │
└─────────────────────────────────────────────────────────────┘
```

| 维度 | 负责四官 | 核心目标 | 生死线 |
|------|---------|---------|--------|
| **稳定性** | 架构官 · 玄极 | 3秒首屏、全球秒开、后端挂了前端照样跑 | 首屏 > 3s = 50%用户流失 |

## 二、四官方案摘要

### 2.1 架构官 · 玄极 — 稳定性方案

**核心结论**：Cloudflare Pages（主）+ Vercel（灾备），月度成本仅 ¥300-400（仅AI生成）。

| 模块 | 关键决策 | 执行要点 |
|------|---------|---------|
| **托管架构** | Cloudflare Pages 为主站 | 300+全球节点、HTTP/3+Brotli零配置、免费无限带宽 |
| **国内备案** | 双轨架构（未来） | `www.mysticdao.app`（海外）+ `cn.mysticdao.app`（国内反向代理） |
| **性能优化** | Vite 代码分割 + WebP/AVIF | 路由懒加载、sharp 批量转换、html2canvas Web Worker 优化 |
| **3D降级** | 三级降级策略 | WebGL2 → WebGL1 → CSS SVG，低端设备自动降级 |
| **AI服务** | AutoDL A100（主）+ RTX4060 Tunnel（备） | Cloudflare Workers 轻量队列、高峰期返回占位图、R2 预生成模板缓存 |
| **监控** | UptimeRobot + Sentry | 双层宕机探测、5000事件/月免费错误追踪、IndexedDB本地数据零上传 |

**技术架构拓扑**（文字版）：
```
用户 → GeoDNS分流 → Cloudflare Pages(主)/Vercel(备)
         ↓
   静态资源(Brotli/HTTP3) + Workers(队列) + R2(WebP/AVIF)
         ↓
   AutoDL A100(生成) + RTX4060(灾备) + R2预生成模板(缓存)
         ↓
   UptimeRobot + Sentry + IndexedDB + CF Analytics
```

### 2.3 体验官 · Mira — 可玩性方案

**核心结论**：可玩性不是加小游戏，是让"使用产品"变成"仪式"。三大核心互动 + 分享机制 + 成长体系。

| 模块 | 优先级 | 关键设计 | 成功指标 |
|------|:------:|---------|---------|
| **每日一签** | P0 | 签筒摇晃动画(0.6s) → 签文弹出 → AI解读 → 生成分享卡片 | 日打开率 > 25%，分享率 > 5% |
| **抽符/抽牌** | P0 | 3D翻转 + CSS shimmer能量流动 → 58张牌池 → 每日限免1次 | 完成率 > 70% |
| **运势速测** | P0 | 五行饼图 + 能量条 + 宜忌标签 → 3-8s仪式感加载 | 排盘完成率 > 60% |
| **社交分享** | P0 | 三尺寸海报(9:16/1:1/4:5) + html2canvas前端生成 < 2s | 分享率 > 5% |
| **命盘档案** | P1 | 首次输入生日生成永久档案 → localStorage → Supabase同步 | 留存率指标 |
| **成长体系** | P1 | 灵力值 + 4级身份(初学者→宗师) + 5枚成就徽章 | 7日留存 > 30% |

**用户留存飞轮**：
```
免费内容(每日一签) → 3秒出结果 → 生成专属海报 → 分享解锁 →
好友点击进入 → 命盘档案沉淀 → 深度付费($4.99) → 长期订阅($9.9/月) →
邀请裂变(双方得券) → 回到免费内容
```

**Mira 的四条铁律**：
1. 宁慢勿快 — 签筒摇晃0.6s不是浪费，是价值
2. 少即是多 — 首屏只放3个入口
3. 截图即设计 — 每个可分享页面都要想象被截图后的样子
4. 数据要诚实 — 埋点从第一天就做好

**核心结论**：增长不是花钱买用户，是让用户买用户。六平台差异化内容 + 三重裂变引擎。

| 模块 | 优先级 | 关键策略 | 成功指标 |
|------|:------:|---------|---------|
| **六平台内容** | P0 | 抖音(娱乐)/快手(下沉)/小红书(审美)/微博(话题)/TikTok(WitchTok)/INS(美学) | 播放量→点击率 > 3% |
| **分享解锁** | P0 | 基础结果 → 分享海报 → 解锁详细解读+高清壁纸 | 分享转化率 > 15% |
| **邀请码裂变** | P0 | 专属邀请码 + 进度可视化 + 四级奖励阶梯 | 邀请率 > 10% |
| **社群裂变** | P1 | 微信社群(国内限量福利) + Discord(海外身份体系) | 社群活跃度 |
| **SEO长尾词** | P1 | 中英文各7个核心词，每词一个独立落地页 | 自然流量占比 > 60% |
| **付费漏斗** | P1 | 免费 → $4.99 → $9.9/月 → $199 | 转化率 > 8% |

**六平台一句话策略**：

|------|------|------|------|
| 抖音 | 娱乐制造机 | "输入生日，AI生成专属护身符" | 主页企业号链接 |

**增长飞轮**：
```
优质内容(六平台) → 精准流量(SEO+社媒) → 产品体验(Aha→习惯→付费) →
裂变分享(海报+邀请码+社群) → 收入回流($4.99→$9.9→$199) → 更多内容投入
```

## 三、四官交叉冲突与协同

### 3.1 已知冲突

| # | 冲突场景 | 涉及四官 | 解决方案（指挥官拍板） |
|---|---------|---------|---------------------|
| 1 | Mira想加3D罗盘动画 → 玄极说性能不够 | 体验官 vs 架构官 | **性能预算制**：3D动画必须能在低端机30fps，否则降级为CSS SVG。首屏禁止加载Three.js，用户主动点击后才懒加载。 |
| 2 | 燎原想搞"转发改运"裂变 → 守律说合规风险 | 增长官 vs 风控官 | **包装替换制**："转发改运"→"分享好运"，绝不承诺结果。海报文案由守律审核后方可上线。 |
| 3 | 守律要求AI水印 → Mira说破坏美感 | 风控官 vs 体验官 | **设计融合制**：水印设计成品牌元素的一部分（右下角古铜金小字"AI Generated · MysticDao"），字体与整体设计统一，≤5%画面。 |
| 4 | 玄极想做PWA → 燎原说App Store才能裂变 | 架构官 vs 增长官 | **分阶段制**：PWA先行（低成本、即时更新），数据验证后再考虑小程序/原生App。分享机制不依赖App Store，靠海报+链接。 |
| 5 | 燎原要六平台同时发力 → 玄极担心国内备案未完成 | 增长官 vs 风控官/架构官 | **区域隔离制**：海外轨（Cloudflare Pages）先上线运营，国内轨（备案完成后）再开放。国内内容在小红书/抖音以"文化科普"为主，不直接导流未备案网站。 |
